# 网络验证（卡密）SaaS 平台 - Product Requirement Document

## Overview

- **Summary**: 构建一套对标 b6w.top 的多合一综合卡密验证 SaaS 平台，集成软件授权验证、套餐订阅、API 接口鉴权、发卡平台四大核心能力，采用 PHP 8 + ThinkPHP 8 + Vue3 + Element Plus 技术栈，支持商户自由注册、三级分销、D+1 结算、生产级安全防护。
- **Purpose**: 解决现有卡密平台功能分散、接入成本高、安全能力不足、分销体系不健全等行业痛点，为中小开发者与软件团队提供一站式商用级卡密验证服务。
- **Target Users**: 超级管理员、平台运营/客服、商户主账号、商户子账号/员工、终端用户、商户分销代理（共 6 类角色）。

## Goals

- 构建完整的商户入驻与套餐订阅体系，支持商户自由注册、四档套餐、订阅+用量混合计费
- 实现生产级卡密验证 API（五重鉴权、五维限流、AES 加密、哈希存储），支持 P99 响应时间 ≤ 50ms
- 提供发卡平台能力，支持商户独立店铺、商品管理、自动发货、彩虹易支付对接
- 实现商户三级分销体系，逐级裂变邀请码、差价+佣金双模式、D+1 结算
- 提供多语言 SDK（易语言、Python、C#、VB、Java），5 分钟快速接入
- 简约商务蓝色主题，仅亮色模式，无 Emoji，响应式完美适配 PC + H5
- Docker Compose + 宝塔面板部署，文件存储可配置（本地/OSS/七牛/MinIO）

## Non-Goals (Out of Scope)

- 平台代理商体系（V1 不做，仅商户分销代理）
- 软件版本管理与在线升级（V2 规划，V1 预留字段）
- 远程函数/云函数（V2 规划，V1 预留接口）
- 插件市场（V2 规划）
- 数据大屏（V1.2 规划）
- 优惠券/促销系统（V2 规划）
- 暗黑模式（不做，仅亮色主题）
- Emoji 表情（界面/文案/文档全面禁用）
- 多语言国际化（仅中文）
- 微信/APP 端原生应用（仅 Web H5 响应式）

## Background & Context

- 对标产品：b6w.top（行业主流卡密验证平台）
- 技术选型依据：PHP + ThinkPHP 是卡密行业主流技术栈，生态成熟、开发效率高、部署简单
- 前端选型：Vue3 + Element Plus，管理后台标配，组件丰富，响应式能力强
- 部署策略：Docker Compose 单机部署 + 宝塔面板运维，兼顾可维护性与成本
- 安全基线：生产级防护，五重鉴权 + 五维限流 + 哈希存储 + 风控告警
- 已有产出：完整 PRD 文档（`/workspace/docs/PRD-网络验证卡密SaaS平台.md`），含 14 章、1836 行、100+ 功能项

## Functional Requirements

### 用户与权限（FR-1）

- FR-1.1: 支持 6 类角色（超管、运营、商户主账号、商户子账号、终端用户、分销代理）
- FR-1.2: RBAC 权限模型，菜单级 + 按钮级 + 数据级三级权限
- FR-1.3: 商户自由注册，邮箱验证，无需审核
- FR-1.4: 商户子账号由商户主账号创建并分配权限
- FR-1.5: 敏感操作（提现、改支付配置、删除卡密）需邮箱验证码二次验证
- FR-1.6: 登录失败 10 次锁定 30 分钟，异地登录邮件提醒

### 商户套餐体系（FR-2）

- FR-2.1: 四档套餐（免费版、基础版、专业版、企业版）
- FR-2.2: 套餐差异维度：应用数量限制、卡密生成总量限制
- FR-2.3: 订阅 + 用量混合计费模式
- FR-2.4: 套餐升级、降级、续费
- FR-2.5: 商户余额充值、流水明细、钱包管理

### 应用管理（FR-3）

- FR-3.1: 应用 CRUD（名称、图标、版本、描述）
- FR-3.2: AppKey + AppSecret 自动生成，Secret 哈希存储
- FR-3.3: IP 白名单配置
- FR-3.4: 设备绑定数量上限配置
- FR-3.5: 应用启用/停用（停用后所有卡密验证失效）

### 卡密管理（FR-4）

- FR-4.1: 单个生成、批量生成（单次最多 10000 张）
- FR-4.2: 卡密格式：24 位 + 自定义前缀 + 混淆大小写字母+数字+符号，支持自定义模板
- FR-4.3: 七种卡密类型：日卡、周卡、月卡、季卡、年卡、永久卡、试用卡
- FR-4.4: 卡密哈希存储（SHA-256），生成时仅展示一次明文
- FR-4.5: 卡密按应用分组，互不通用
- FR-4.6: 卡密状态管理：未使用、已激活、已到期、已封禁、已作废
- FR-4.7: 设备绑定（机器码/MAC/硬件指纹），支持自定义绑定数量
- FR-4.8: 换绑/解绑，支持次数限制
- FR-4.9: 软失效 + 可恢复期 + 续费激活
- FR-4.10: 卡密防爆破：5 分钟内失败 15 次自动封 IP + 卡密
- FR-4.11: 卡密批量导入、导出 Excel/CSV

### 验证 API（FR-5）

- FR-5.1: 卡密验证接口
- FR-5.2: 卡密激活接口（首次绑定设备）
- FR-5.3: 设备换绑接口
- FR-5.4: 卡密查询接口
- FR-5.5: 卡密生成接口（API 方式）
- FR-5.6: 心跳保活接口（超时踢下线）
- FR-5.7: 在线人数查询接口
- FR-5.8: 变量/公告接口（远程读取配置）
- FR-5.9: 用户注册/登录接口
- FR-5.10: 卡密兑换/充值接口
- FR-5.11: 统一 JSON 返回格式
- FR-5.12: 五重鉴权：AppKey+Secret 签名 + AccessToken + IP 白名单 + HTTPS + 时间戳
- FR-5.13: 防重放：时间戳 + Nonce 机制
- FR-5.14: 请求/响应 AES 整体加密
- FR-5.15: 五维限流（卡密/IP/设备/应用/商户），超管配置阈值

### SDK 与接入文档（FR-6）

- FR-6.1: 易语言 SDK
- FR-6.2: Python SDK
- FR-6.3: C# SDK
- FR-6.4: VB SDK
- FR-6.5: Java SDK
- FR-6.6: 接入文档与示例代码

### 发卡平台（FR-7）

- FR-7.1: 商户独立发卡店铺
- FR-7.2: 平台统一卡密市场
- FR-7.3: 商品 CRUD（名称、图片、描述、分类、价格、库存、上下架）
- FR-7.4: 商品类型：卡密（自动发货）、其他数字商品
- FR-7.5: 限购配置（每人/每 IP/每设备）
- FR-7.6: 单品类购买（无购物车）
- FR-7.7: 支付成功后页面显示卡密 + 邮件发送
- FR-7.8: 订单查询（凭订单号/邮箱）
- FR-7.9: 订单超时 10 分钟自动关闭
- FR-7.10: 商户店铺自定义装修（logo、配色、轮播图）

### 支付与财务（FR-8）

- FR-8.1: 彩虹易支付对接（超管全局配置）
- FR-8.2: 商户可选自有支付通道
- FR-8.3: 商户余额充值
- FR-8.4: 钱包流水明细（收入、支出、提现、冻结）
- FR-8.5: 订单管理（状态、退款、导出）

### 商户三级分销（FR-9）

- FR-9.1: 四级结构：商户 → 一级代理 → 二级代理 → 三级代理
- FR-9.2: 差价模式 + 佣金模式并存
- FR-9.3: 代理等级与价格/佣金由商户后台设置
- FR-9.4: 逐级裂变：每个节点（商户/一级/二级）有独立邀请码/链接，注册即终身绑定
- FR-9.5: 三级硬限制：三级代理不可再发展下级
- FR-9.6: 佣金进代理钱包余额
- FR-9.7: D+1 结算，最低提现 1 元，手续费 3%
- FR-9.8: 余额可抵扣进货
- FR-9.9: 佣金明细、提现记录
- FR-9.10: 代理树视图，商户可查看完整分销树

### 数据统计与仪表盘（FR-10）

- FR-10.1: 超管仪表盘（商户/代理/卡密/订单/收入/API/在线数/工单/公告 全维度）
- FR-10.2: 商户仪表盘（应用/卡密状态/API 额度/发卡收入/代理/在线设备/工单/续费提醒）
- FR-10.3: 商户自定义数据看板
- FR-10.4: 代理仪表盘（推广代理数/佣金/下级/明细/推广链接数据）
- FR-10.5: 数据导出 Excel/CSV（卡密/订单/佣金/日志全支持）
- FR-10.6: 定时报表邮件发送

### 安全与风控（FR-11）

- FR-11.1: 注册风控（同 IP 注册限制、邮箱验证）
- FR-11.2: 异常订单监控（短时间大量下单）
- FR-11.3: 异常 API 调用监控（突发流量告警）
- FR-11.4: 商户异常行为检测
- FR-11.5: 黑名单机制（IP/设备/手机/邮箱）
- FR-11.6: 异常告警通知（邮件通知超管）
- FR-11.7: 操作日志全记录（who/when/what/IP/UA）

## Constraints

- **Technical**:
  - 后端：PHP 8 + ThinkPHP 8
  - 前端：Vue 3 + Element Plus
  - 数据库：MySQL 8.x + Redis + 时序数据库（InfluxDB 或 ClickHouse）
  - 消息队列：Redis Queue 或 RabbitMQ
  - 部署：Docker Compose + 宝塔面板
  - 文件存储：可配置驱动（本地/OSS/七牛/MinIO）
  - UI：仅亮色主题、禁用 Emoji、简约商务蓝色风
  - 仅中文界面

- **Business**:
  - 千级商户规模
  - D+1 结算周期
  - 三级分销（法律合规红线内）
  - 最低提现 1 元，手续费 3%

- **Dependencies**:
  - 彩虹易支付（第三方支付通道）
  - 邮件服务（SMTP）
  - CDN 服务（静态资源加速）
  - 对象存储服务（可选）

## Assumptions

- 商户具备基本的技术能力，能看懂 SDK 文档并完成接入
- 彩虹易支付服务稳定可用，满足商户收款需求
- 单机部署可支撑千级商户规模的初始阶段
- PHP + ThinkPHP 的开发效率可满足项目节奏
- 三级分销模式在合法合规范围内运作
- 终端用户的软件客户端能按 SDK 规范实现验证逻辑

## Acceptance Criteria

### AC-1: 商户自由注册与登录
- **Given**: 访客访问商户注册页面
- **When**: 填写用户名、邮箱、密码，完成邮箱验证码验证
- **Then**: 商户账号创建成功，自动登录，默认开通免费版套餐
- **Verification**: `programmatic`

### AC-2: 应用创建与密钥生成
- **Given**: 商户已登录，套餐内应用配额充足
- **When**: 填写应用名称、版本、描述，提交创建
- **Then**: 应用创建成功，生成 AppKey 和 AppSecret，Secret 明文仅展示一次
- **Verification**: `programmatic`

### AC-3: 批量生成卡密
- **Given**: 商户已创建应用，卡密额度充足
- **When**: 选择应用、卡密类型、数量（≤10000）、前缀、字符集、长度，提交生成
- **Then**: 生成对应数量的卡密，明文列表仅展示一次，数据库以 SHA-256 哈希存储
- **Verification**: `programmatic`

### AC-4: 卡密验证 API 正常响应
- **Given**: 存在有效未使用卡密，AppKey/Secret 正确
- **When**: 客户端构造签名请求，调用卡密验证接口
- **Then**: 返回 JSON 格式验证结果，P99 响应时间 ≤ 50ms
- **Verification**: `programmatic`

### AC-5: 卡密验证五重鉴权通过
- **Given**: 客户端发起验证请求
- **When**: 签名错误 / 时间戳过期 / Nonce 重复 / IP 不在白名单 / 触发限流
- **Then**: 返回对应错误码，拒绝访问
- **Verification**: `programmatic`

### AC-6: 设备绑定与换绑
- **Given**: 卡密已激活，绑定设备数未达上限
- **When**: 新设备发起激活请求
- **Then**: 设备绑定成功，绑定数 +1；达上限则拒绝
- **Verification**: `programmatic`

### AC-7: 发卡购买与自动发货
- **Given**: 发卡商品上架且有库存
- **When**: 用户下单并完成支付
- **Then**: 自动从卡密池取卡密，页面显示明文 + 邮件发送，订单状态变为已支付
- **Verification**: `programmatic`

### AC-8: 订单超时自动关闭
- **Given**: 已创建待支付订单
- **When**: 超过 10 分钟未支付
- **Then**: 订单自动关闭，库存释放
- **Verification**: `programmatic`

### AC-9: 三级分销逐级裂变
- **Given**: 商户生成邀请码
- **When**: 一级通过商户邀请码注册 → 一级生成邀请码 → 二级注册 → 二级生成邀请码 → 三级注册
- **Then**: 形成商户→一级→二级→三级树状结构，终身绑定
- **Verification**: `programmatic`

### AC-10: 三级代理不可再发展下级
- **Given**: 存在三级代理账号
- **When**: 三级代理尝试生成邀请码，或新用户用三级邀请码注册
- **Then**: 拒绝操作，提示已达三级上限
- **Verification**: `programmatic`

### AC-11: 佣金 D+1 结算
- **Given**: 代理推广的订单支付成功
- **When**: 经过 1 个自然日（D+1）
- **Then**: 佣金解冻进入可用余额，可提现或抵扣进货
- **Verification**: `programmatic`

### AC-12: 卡密防爆破封禁
- **Given**: 某卡密或 IP 连续验证失败
- **When**: 5 分钟内失败达 15 次
- **Then**: 自动封禁该卡密 + IP，需手动解封
- **Verification**: `programmatic`

### AC-13: 数据导出功能
- **Given**: 商户在列表页选择筛选条件
- **When**: 点击导出按钮
- **Then**: 生成 Excel/CSV 文件并下载，数据符合筛选条件
- **Verification**: `programmatic`

### AC-14: UI 风格符合规范
- **Given**: 用户访问任意页面
- **When**: 浏览页面内容
- **Then**: 简约商务蓝色风格，无 Emoji，仅亮色主题，响应式布局适配当前设备
- **Verification**: `human-judgment`

### AC-15: 敏感操作二次验证
- **Given**: 商户/超管已登录
- **When**: 执行提现、删除卡密、修改支付配置等敏感操作
- **Then**: 弹出邮箱验证码二次验证弹窗，验证通过方可执行
- **Verification**: `programmatic`

### AC-16: 操作日志全记录
- **Given**: 用户执行任意操作
- **When**: 操作执行完成
- **Then**: 操作日志记录包含用户、IP、UA、操作类型、对象、请求数据、时间
- **Verification**: `programmatic`

### AC-17: Docker Compose 一键部署
- **Given**: 服务器已安装 Docker 和 Docker Compose
- **When**: 执行 `docker-compose up -d`
- **Then**: 所有服务（Nginx、PHP、MySQL、Redis、消息队列）正常启动，平台可访问
- **Verification**: `programmatic`

### AC-18: SDK 可用且文档完整
- **Given**: 开发者获取 SDK
- **When**: 按照文档步骤接入
- **Then**: 5 分钟内完成基本验证功能接入，SDK 示例代码可运行
- **Verification**: `human-judgment`
