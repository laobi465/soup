# 1. 项目概述

## 1.1 项目背景

当前网络验证（卡密）行业存在以下痛点：

- 现有平台（如 b6w.top）功能分散，软件授权、套餐订阅、API 鉴权、发卡平台往往需要多套系统组合
- 商户接入成本高，缺乏一站式解决方案
- 安全防护能力参差不齐，卡密泄露、API 滥用事件频发
- 分销体系不健全，商户难以高效拓展销售渠道

本项目旨在构建一套对标 b6w.top 的多合一综合卡密验证 SaaS 平台，集成软件授权验证、套餐订阅、API 接口鉴权、发卡平台四大核心能力，面向中小开发者与软件团队提供商用级服务。

## 1.2 项目目标

| 维度 | 目标 |
|------|------|
| 商业目标 | 服务千级商户规模，成为业内主流卡密验证 SaaS 平台之一 |
| 产品目标 | 四合一能力（软件授权 + 套餐订阅 + API 鉴权 + 发卡），一站式接入 |
| 安全目标 | 生产级防护（签名 + 加密 + 限流 + 哈希存储 + 风控告警） |
| 体验目标 | 商户 5 分钟接入、终端用户秒级验证、响应式完美适配 |

## 1.3 适用用户与角色

本平台共 6 类用户角色：

| 编号 | 角色名称 | 角色说明 | 入驻方式 |
|------|---------|---------|---------|
| R1 | 超级管理员 | 平台拥有者，全权管理 | 系统初始化 |
| R2 | 平台运营/客服 | 日常运营、工单处理、数据查看 | 超管创建 |
| R3 | 商户主账号 | 平台付费客户，运营自己的应用与卡密 | 自由注册 |
| R4 | 商户子账号/员工 | 商户主账号创建的员工账号 | 商户创建 |
| R5 | 终端用户 | 卡密持有者，使用卡密激活软件 | 自主激活 |
| R6 | 商户分销代理 | 商户通过邀请码发展的代理（最多三级） | 邀请码注册 |

## 1.4 产品核心价值

1. **四合一能力**：软件授权 + 套餐订阅 + API 鉴权 + 发卡，单一平台覆盖全部场景
2. **生产级安全**：五重鉴权 + 五维限流 + 哈希存储 + 风控告警
3. **三级分销**：商户可发展三级代理，逐级裂变，差价与佣金双模式
4. **零门槛接入**：5 种语言 SDK + 完整文档，5 分钟快速接入
5. **灵活部署**：Docker Compose + 宝塔面板，文件存储可配置（本地/OSS/七牛/MinIO）

## 2.2 系统架构说明

### 2.2.1 技术架构

```
┌──────────────────────────────────────────────────────┐
│                    前端层（Vue3）                      │
│   管理后台（超管/商户）  +  发卡平台用户端（H5/PC）     │
└────────────────────────┬─────────────────────────────┘
                         │ HTTPS
┌────────────────────────▼─────────────────────────────┐
│              接入层（Nginx 负载均衡 + CDN）            │
└────────────────────────┬─────────────────────────────┘
                         │
┌────────────────────────▼─────────────────────────────┐
│              应用层（PHP 8 + ThinkPHP 8）              │
│   API 服务 / 管理后台服务 / 发卡服务 / 定时任务         │
└──┬──────────┬──────────┬──────────┬──────────────────┘
   │          │          │          │
   ▼          ▼          ▼          ▼
┌──────┐ ┌────────┐ ┌─────────┐ ┌──────────────┐
│MySQL │ │ Redis  │ │消息队列  │ │ 时序数据库    │
│ 8.x  │ │ 缓存/  │ │ 异步任务 │ │ API日志/统计  │
│      │ │ 限流   │ │          │ │              │
└──────┘ └────────┘ └─────────┘ └──────────────┘
```

### 2.2.2 部署架构

- 单机部署：Docker Compose 编排（MySQL + Redis + PHP-FPM + Nginx + 时序数据库 + 消息队列）
- 运维管理：宝塔面板管理基础环境，Docker 管理应用容器
- 文件存储：可配置驱动（本地 / 阿里云 OSS / 腾讯云 COS / 七牛云 / MinIO）
- CDN 加速：静态资源与发卡页面走 CDN

## 2.3 业务闭环逻辑说明

平台业务闭环由四条主线构成：

1. **商户入驻闭环**：自由注册 → 邮箱验证 → 免费版开通 → 升级套餐 → 创建应用 → 生成卡密 → 接入 SDK → 上线运营
2. **卡密流通闭环**：商户生成 → 入库 → 分发（发卡/分销）→ 终端用户激活 → 验证 → 心跳保活 → 到期/续费
3. **资金流转闭环**：用户付款 → 卡密自动发货 → 收入入商户账户 → 代理佣金 D+1 结算 → 提现到账
4. **分销裂变闭环**：商户生成邀请码 → 一级注册 → 一级生成邀请码 → 二级注册 → 二级生成邀请码 → 三级注册（不可再裂变）

## 3.3 菜单权限规则

- 菜单按角色动态渲染，登录后根据 `role_type` 返回对应菜单树
- 商户子账号（R4）菜单由商户主账号（R3）在「子账号管理」中分配
- 不可访问的菜单不渲染、URL 直接访问返回 403

## 3.4 按钮权限规则

- 按钮权限基于 RBAC，权限标识符格式：`模块:资源:操作`（如 `card:list`、`card:create`）
- 商户子账号按钮权限由商户主账号分配，未授权按钮不渲染
- 敏感操作按钮（删除、提现、改支付配置）即使有权限也需二次验证

## 3.5 数据权限规则

| 角色 | 数据范围 |
|------|---------|
| 超管 R1 | 全平台所有数据 |
| 平台运营 R2 | 全平台数据，但只读（除工单、公告） |
| 商户主账号 R3 | 仅本人商户下的数据（应用、卡密、订单、代理等） |
| 商户子账号 R4 | 由 R3 分配的数据范围（按应用/按模块） |
| 终端用户 R5 | 仅本人卡密与订单 |
| 分销代理 R6 | 仅本人及下级代理数据 |

## 3.6 账号状态规则

| 状态 | 说明 | 触发条件 | 影响 |
|------|------|---------|------|
| 正常 | 可正常登录使用 | 注册成功 / 解封 | 全功能可用 |
| 禁用 | 不可登录 | 超管封禁 / 商户封禁子账号 | 立即登出，提示「账号已禁用」 |
| 锁定 | 临时不可登录 | 连续登录失败 10 次 | 锁定 30 分钟，自动解锁 |
| 过期 | 商户套餐到期 | 套餐到期未续费 | 商户后台只读，API 停止服务，发卡店铺下线 |

# 4. 全局通用规则

## 4.1 全局配色、样式、交互规范

### 4.1.1 主题规范

- **视觉风格**：简约商务风
- **主色调**：蓝色系（建议 #1890FF / #1677FF）

# 5. 登录与账号体系

## 5.1 登录页面规则

### 5.1.1 登录入口

- 平台管理后台：`/admin/login`（超管、运营、商户、商户子账号）
- 发卡平台用户端：`/shop/login`（终端用户）
- 代理后台：`/agent/login`（分销代理）

### 5.1.2 登录字段

| 字段 | 类型 | 必填 | 校验规则 |
|------|------|------|---------|
| 账号 | 文本 | 是 | 用户名或邮箱 |
| 密码 | 密码 | 是 | 6-32 位，字母+数字 |
| 验证码 | 文本 | 是 | 图形验证码（失败 3 次后出现） |
| 记住我 | 勾选 | 否 | 7 天免登录 |

### 5.1.3 登录流程

```
输入账号密码 → 图形验证码（失败 3 次后）→ 提交
→ 服务端校验 → 失败：累计失败次数，达 10 次锁定 30 分钟
→ 成功：生成 Token，返回用户信息与菜单权限
→ 若为敏感操作场景：触发邮箱验证码二次验证
```

## 5.2 Token 过期规则

- Token 有效期：7 天（记住我）/ 2 小时（不记住）
- Token 续期：每次请求自动续期
- Token 失效：返回 401，前端跳转登录页

## 5.3 登录超时、异地登录

### 5.3.1 登录超时

- 后台无操作 30 分钟自动登出
- 提示：「登录已超时，请重新登录」

### 5.3.2 异地登录

- 检测登录 IP 与上次登录 IP 不在同一城市
- 邮件通知账号主人「检测到异地登录」
- 不强制拦截，仅提醒

## 5.4 密码规则、找回密码

### 5.4.1 密码规则

- 长度 6-32 位
- 必须包含字母 + 数字
- 建议包含特殊字符（非强制）
- 密码哈希存储（bcrypt）

### 5.4.2 找回密码流程

```
点击「忘记密码」→ 输入注册邮箱 → 发送重置链接邮件
→ 用户点击邮件链接 → 输入新密码 → 重置成功 → 跳转登录
```

- 重置链接有效期 30 分钟
- 重置后所有 Token 失效

## 5.5 头像、个人信息修改

- 头像上传：图片 ≤ 2MB
- 修改昵称、邮箱、手机号
- 修改密码：需输入旧密码 + 新密码 + 确认新密码
- 修改邮箱：需新邮箱验证码

# 7. 核心业务流程 PRD

## 7.1 商户入驻流程

```
[开始] → 访问平台注册页
→ 填写：用户名/邮箱/密码/图形验证码
→ 提交 → 邮箱验证码验证
→ 验证通过 → 创建商户账号（默认免费版）
→ 自动登录 → 进入商户仪表盘
→ 引导：创建应用 → 生成卡密 → 接入 SDK
```

**异常场景**：
- 用户名已存在：提示「用户名已被占用」
- 邮箱已注册：提示「邮箱已注册，请直接登录」
- 邮箱验证码错误：提示「验证码错误或已过期」
- 注册失败：提示「注册失败，请稍后重试」

## 7.2 卡密生成与分发流程

```
[商户后台] → 卡密管理 → 生成卡密
→ 选择应用、类型、数量、前缀、长度、字符集
→ 确认生成 → 系统按配置生成卡密
→ 卡密明文返回（仅展示一次）+ 哈希入库
→ 状态：未使用
→ 分发渠道：
   a) 商户手动复制发卡
   b) 商户导入发卡平台售卖
   c) 代理进货后分发
[结束]
```

**异常场景**：
- 应用已停用：提示「应用已停用，无法生成卡密」
- 套餐卡密额度不足：提示「套餐卡密额度不足，请升级套餐」
- 单次生成超上限（10000）：提示「单次最多生成 10000 张」

## 7.3 卡密验证流程（核心）

```
[客户端] 构造请求（AppKey + 签名 + 时间戳 + Nonce + AES 加密 payload）
→ [Nginx] 负载均衡转发
→ [API 服务]
→ 1. 签名校验（AppKey + AppSecret HMAC-SHA256）
→ 2. 时间戳校验（超过 5 分钟拒绝）
→ 3. Nonce 防重放（Redis 记录已用 Nonce）
→ 4. IP 白名单校验
→ 5. 五维限流（卡密/IP/设备/应用/商户）
→ 6. 解密 payload
→ 7. 业务逻辑：
   a) 查询卡密（哈希匹配）
   b) 校验卡密状态（未使用/已激活/已到期/已封禁/已作废）
   c) 校验绑定设备（已达上限则拒绝）
   d) 首次激活：绑定设备，状态改为已激活，计算到期时间
   e) 心跳保活：更新最后心跳时间
→ 8. AES 加密响应
→ 9. 返回 JSON
→ 10. 异步记录调用日志（时序数据库）
[结束]
```

**异常场景**：

| 场景 | 返回码 | 处理 |
|------|-------|------|
| 签名错误 | 4001 | 拒绝 |
| 时间戳过期 | 4002 | 拒绝 |
| Nonce 重复 | 4003 | 拒绝 |
| IP 不在白名单 | 4004 | 拒绝 |
| 限流触发 | 4005 | 拒绝 + 封 IP/卡密 |
| 卡密不存在 | 4101 | 拒绝 |
| 卡密已到期 | 4102 | 拒绝 |
| 卡密已封禁 | 4103 | 拒绝 |
| 卡密已作废 | 4104 | 拒绝 |
| 设备绑定达上限 | 4105 | 拒绝 |
| 应用已停用 | 4106 | 拒绝 |
| 商户已过期 | 4107 | 拒绝 |
| 心跳超时 | 4108 | 踢下线 |

## 7.4 发卡购买流程

```
[用户] 访问发卡店铺 → 选商品 → 下单
→ 限购校验（每人/每IP/每设备）
→ 创建订单（状态：待支付，超时 10 分钟）
→ 跳转彩虹易支付
→ 支付成功
→ 回调通知平台
→ 从卡密池取未使用卡密 → 标记已售
→ 页面显示卡密明文 + 发送邮件
→ 商户账户入账（按支付通道路由）
→ 若有代理：D+1 计算佣金进代理钱包
→ 订单状态：已支付
[结束]
```

**异常场景**：
- 库存不足：提示「库存不足，无法下单」
- 限购达上限：提示「已达限购上限」
- 支付超时：订单自动关闭，释放库存
- 支付失败：订单状态保持待支付，可重新支付
- 卡密池无可用卡密：订单标记异常，通知商户补货，自动退款

## 7.5 卡密到期与续费流程

```
[定时任务] 扫描即将到期卡密（提前 7/3/1 天）
→ 发送邮件提醒终端用户
→ 卡密到期 → 状态改为已到期（软失效）
→ 进入可恢复期（默认 30 天）
→ 续费：
   a) 用户在发卡平台购买续费商品
   b) 或商户手动续费
→ 续费成功 → 到期时间延长（在原到期基础上 + 续费时长）
→ 状态恢复为已激活
→ 可恢复期过期 → 永久作废
[结束]
```

## 7.6 分销代理发展流程

```
[商户] 后台生成邀请码/链接 → 分享
→ [新用户] 通过邀请链接注册
→ 终身绑定该商户 → 成为一级代理（level=1）
→ 自动生成一级代理专属邀请码
→ [一级代理] 分享自己的邀请码
→ [新用户] 通过一级邀请码注册 → 成为二级代理（level=2）
→ 自动生成二级代理专属邀请码
→ [二级代理] 分享邀请码
→ [新用户] 通过二级邀请码注册 → 成为三级代理（level=3）
→ 三级代理不再生成有效邀请码（已达上限）
→ [新用户] 尝试通过三级邀请码注册 → 拒绝，提示「已达三级上限」
[结束]
```

## 7.7 佣金结算与提现流程

```
[订单成交] → 计算各级代理佣金
→ 按层级关系逐级分配（一级 X%、二级 Y%、三级 Z%）
→ 佣金进入冻结状态（防退款作弊）
→ D+1 解冻，进入代理可用余额
→ [代理] 发起提现
→ 校验：金额 ≥ 1 元、余额充足
→ 扣除 3% 手续费
→ 提现记录创建（状态：处理中）
→ D+1 到账
→ 状态改为已到账
[结束]
```

## 8.2 关键字段说明

# 11. 安全机制需求

## 11.1 权限安全

- RBAC 权限模型，菜单 + 按钮 + 数据三级权限
- Token 鉴权，有效期 2 小时（不记住）/ 7 天（记住）
- 敏感操作二次验证（邮箱验证码）
- 操作日志全记录

## 11.2 数据安全

- 卡密哈希存储（SHA-256）
- AppSecret 哈希存储（bcrypt）
- 密码哈希存储（bcrypt）
- API 请求/响应 AES 加密
- 数据库连接加密（SSL）
- 备份加密存储

## 11.3 防重复提交

- 表单提交：按钮 loading + 后端幂等令牌
- 支付订单：订单号唯一 + 状态机校验
- 卡密生成：批次号唯一 + 数量校验

## 11.4 登录风控

- 登录失败 10 次锁定 30 分钟
- 图形验证码（失败 3 次后强制）
- 异地登录邮件提醒
- IP 黑名单

## 11.5 数据删除安全

- 软删除（标记删除时间，不物理删除）
- 敏感数据物理删除需超管二次确认 + 验证码
- 删除前自动备份

## 11.6 API 安全（核心）

- 五重鉴权：AppKey+Secret 签名 + AccessToken + IP 白名单 + HTTPS + 时间戳
- 防重放：Nonce 机制
- 五维限流：卡密/IP/设备/应用/商户
- 卡密防爆破：5 分钟内失败 15 次自动封 IP+卡密
- 请求/响应 AES 整体加密

## 11.7 风控告警

- 异常登录告警
- 异常订单告警（短时间大量下单）
- 异常 API 告警（突发流量、错误率飙升）
- 商户异常行为告警（生成卡密不验证、长期不活跃）
- 告警方式：邮件 + 站内通知

# 13. 风险点与开发注意事项

## 13.1 法律合规风险

| 风险 | 应对 |
|------|------|
| 三级分销涉传销红线 | 法务审核代理协议与佣金规则文案，确保层级透明、佣金比例合理 |
| 卡密用于灰产 | 用户协议明确禁止用途，保留配合执法权利，违规商户立即封禁 |
| 资金合规 | 提现规则透明，保留全部流水记录备查 |
| ICP 备案 | 平台域名需 ICP 备案，可能需增值电信业务许可证 |

## 13.2 资金安全风险

| 风险 | 应对 |
|------|------|
| 提现薅羊毛 | 新户冷静期（注册 7 天内不可提现）、首笔提现延迟 |
| 商户跑路 | 平台保留干预能力，异常商户可冻结资金 |
| 退款作弊 | 佣金 D+1 结算（防退款后佣金已发） |

## 13.3 技术风险

| 风险 | 应对 |
|------|------|
| API 高并发扛不住 | Redis 缓存卡密状态、限流计数器，避免直接打 DB |
| 卡密池泄露 | 生成接口加二次验证 + 操作日志 + 异常告警 |
| 哈希存储后无法找回明文 | 提供「重置卡密」能力，工单场景使用 |
| Docker 单机性能瓶颈 | 预留 K8s 升级路径，关键服务可拆分 |
| 宝塔与 Docker 冲突 | 明确分工：宝塔管基础环境，Docker 管应用 |
| 备份不可恢复 | 定期验证备份可恢复性 |

## 13.4 开发注意事项

1. **分阶段开发**：
   - V1.0：核心闭环（商户 + 应用 + 卡密 + 验证 API + 发卡 + 支付 + 基础统计）
   - V1.1：分销体系（三级分销 + 邀请码 + 佣金结算）
   - V1.2：风控告警 + 数据大屏
   - V2.0：扩展功能（云函数、插件市场等）

2. **API 性能优先**：验证接口是高频核心，Redis 缓存卡密状态、限流计数器

3. **卡密哈希存储务必落地**：生成时返回明文一次，UI 明确提示保存

4. **分销层级用闭包表**：查询高效，支持多级查询

5. **支付通道抽象**：定义 PaymentDriver 接口，彩虹易支付 / 商户自配都实现该接口

6. **SDK 独立仓库**：5 种语言 SDK 各自独立 Git 仓库，版本化管理

7. **时序数据库选型**：建议 InfluxDB 或 ClickHouse，存 API 日志与统计

8. **测试覆盖**：核心流程（验证 API、支付、佣金结算）需 100% 测试覆盖
